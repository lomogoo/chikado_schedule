# チカ堂 SCHEDULE

チカ堂（サンモール一番町・旧金港堂跡地 地下空間）の**施設利用スケジュール管理アプリ**です。

- 📅 **月別ビュー**（1 画面 = 1 か月。縦スクロールで月がスナップ切り替え）
- 🕒 **3日間ビュー**（横スクロールで前後の日へ。30分単位・終日帯つき）
- 📌 **イベント相談掲示板**（日程未定の利用希望を付箋で貼る → そのままカレンダーへ）
- 📮 **外部向け問い合わせフォーム**（`inquiry.html`）。URL を渡すだけで、外部の方が掲示板へ直接相談を貼れます
- 🗓 **日をまたぐ連続利用**に対応（開始日時 → 終了日時）＋**終日**指定
- 🏷 **仮予約（未確定）** と **本予約（確定）** を区別
- 🔔 予定・相談の追加や更新を**ポップアップで通知**。既読 / 未読は端末ごとに管理
- ⚠️ **実施 1 か月前になった仮予約**をカレンダー上で強調＋通知
- 📝 利用内容・利用者・**チカ堂担当者**などを記録
- ☁️ データは **Supabase**（PostgREST）で管理
- ⚪️ 白背景のみ（ダークモードなし）／ポスターのトンマナ（墨黒・ピンク・ストーングレー）準拠

ビルド不要の静的サイトです（依存パッケージ 0）。`index.html` を開けばそのまま動きます。

## 画面

| ビュー | 説明 |
| --- | --- |
| 月 | **1 画面にちょうど 1 か月**が収まり、縦スクロールで月がスナップして切り替わります（月の途中で止まりません）。日付の数字をタップするとその日から 3 日間ビューへ。空白部分をタップで新規予約。 |
| 3日間 | 30 分刻みのタイムグリッド。画面には 3 日ぶんが収まり、**横スクロールで前後の日**を確認できます。空きスロットをタップするとその時間で新規予約フォームが開きます。重なった予約は自動で横に並びます。 |
| 掲示板 | 日程が決まっていない利用希望を**付箋**として貼る場所。日程が固まったらその付箋からカレンダーへ移せます。上部から**外部向けフォームの URL コピー / フォームを開く**ができます。 |

### 日をまたぐ予約の表示

予約は「開始日時 → 終了日時」の連続した区間です。3 日間ビューでは自動的に分解されます。

| その日の扱い | 表示 |
| --- | --- |
| 初日 | 開始時刻 〜 24:00 のブロック |
| 中日（まるまる 1 日） | ヘッダー下の**「終日」帯**に横長の帯として表示 |
| 最終日 | 0:00 〜 終了時刻のブロック |

月別ビューでは各日にチップが並び、`2/4` のような通し番号が付きます。

### 掲示板の付箋

| 見た目 | 意味 |
| --- | --- |
| 白い付箋 | 相談中の施設予約 |
| ピンクの付箋 | 日程確定 |
| グレーの付箋 | 見送り |
| **黄色い付箋**＋「その他の問い合わせ」タグ | 施設予約以外の問い合わせ（`category = 'other'`） |
| **ピンクの左帯**＋「担当者 未定」バッジ | チカ堂担当者がまだ決まっていない相談 |

フィルターは **すべて / 相談中 / 日程確定 / その他** の 4 つです。
「その他」だけは状態ではなく**種別**での絞り込みなので、相談中の「その他」は
「相談中」と「その他」の両方に出てきます。

### 外部向け問い合わせフォーム（`inquiry.html`）

施設を使いたい外部の方が、アプリを開かずに掲示板へ直接相談を貼れる公開ページです。
保存先はアプリ内の「相談を貼る」とまったく同じ `chikado_inquiries` なので、
送信された内容はそのまま付箋として掲示板に並びます。

公開 URL: <https://lomogoo.github.io/chikado_schedule/inquiry.html>

- 掲示板の上部にある「外部向け問い合わせフォーム」から **URL をコピー / フォームを開く** ができます
- **チカ堂担当者は聞きません**（空欄で登録され、掲示板側で「担当者 未定」と強調されます）
- ご相談の内容で 2 つに分岐します
  - **施設予約**（既定）… 件名・希望時期・利用内容・お名前・連絡先・想定人数・備考
  - **その他** … 件名・お問い合わせ内容の自由記述＋お名前・連絡先のみ
- 連絡先は**メールアドレス**と**電話番号**の 2 欄。どちらか一方は必須です
- 送信されたレコードには `source = 'public'` が入り、相談詳細に「外部フォームから」と表示されます

### お知らせ（ポップアップ通知）

ヘッダーのベルに未読件数が出ます。未読があるときは自動でポップアップが開きます。

| 種別 | 条件 |
| --- | --- |
| **新規** | この端末でまだ見ていない予定が追加された |
| **更新** | 前回確認したときから日時・区分・件名が変わった |
| **掲示板** | 相談が新しく貼られた / 更新された |
| **要確認** | 仮予約のまま実施日が 30 日以内に迫っている |

既読状態はサーバーではなく**この端末の `localStorage`**（予約 ID をキー）に保存されます。
端末ごとに独立して管理されるため、他の人の既読には影響しません。
初回訪問時は既存の予定をすべて既読として扱うため、過去分の通知で埋まることはありません。

「要確認」の予定は、カレンダー上でもピンクの塗り＋`!` マーク（狭い画面では左端の太線）で
強調されます。

## セットアップ

### 1. Supabase 側

セットアップ用の SQL は**リポジトリには含めず、別途共有**しています。
Supabase の **SQL Editor** に貼り付けて実行してください。
このアプリ専用の `public.chikado_reservations` テーブルを新規作成します
（既存の `reservations` テーブルには一切触れません）。

> 列を追加するマイグレーション（`contact_email` / `contact_phone` / `category` / `source`）も
> 同じく別途共有しています。**アプリを更新する前に SQL を先に流してください。**
> アプリは新しい列を明示的に指定して読み書きするため、列が無いと通信がエラーになります。

### 2. 接続設定

`js/config.js` に Supabase の URL と publishable key を記載しています。

```js
export const SUPABASE_URL = 'https://tfkzsbwhvhgxbnnfwtou.supabase.co';
export const SUPABASE_KEY = 'sb_publishable_...';
```

publishable key（旧 anon key）は**ブラウザに公開される前提の鍵**なので、リポジトリに含めて問題ありません。
`service_role` キーは絶対にここへ置かないでください。

### 3. ローカルで動かす

ES Modules を使っているため、`file://` ではなく HTTP で開いてください。

```bash
python3 -m http.server 8000
# → http://localhost:8000
```

## データ構造

`public.chikado_reservations`（このアプリ専用。既存の `reservations` とは分離）

| 列 | 型 | 説明 |
| --- | --- | --- |
| `id` | uuid | 主キー |
| `start_date` | date | 利用開始日 |
| `end_date` | date | 利用終了日（単日なら開始日と同じ） |
| `start_time` | time | 開始時刻（30分単位） |
| `end_time` | time | 終了時刻（30分単位・`24:00` まで可。日をまたぐ場合は開始より小さい値になり得る） |
| `title` | text | 件名（必須） |
| `purpose` | text | **利用内容**（必須） |
| `status` | text | `tentative`（仮予約） / `confirmed`（本予約） |
| `organizer` | text | 利用者・団体名 |
| `contact_email` | text | メールアドレス（任意） |
| `contact_phone` | text | 電話番号（任意） |
| `contact` | text | 連絡先（旧・単一欄。表示のみに使用） |
| `staff` | text | **チカ堂側の担当者**（任意） |
| `headcount` | integer | 人数 |
| `notes` | text | 備考 |
| `created_at` | timestamptz | 作成日時 |
| `updated_at` | timestamptz | 更新日時（トリガーで自動更新） |

日時を `date` + `time` で保持しているため、タイムゾーン変換による時刻ズレが起きません
（施設予約は常に現地時間＝JST で運用されるため）。

**期間の考え方**：`start_date` の `start_time` から `end_date` の `end_time` まで
**連続して**施設を押さえる、というモデルです（例：8/5 15:00 → 8/8 12:00）。
そのため終了時刻が開始時刻より小さくなることがあり、DB の制約も
`end_date > start_date or end_time > start_time` で判定しています。
終日は `00:00`〜`24:00` として保存されます。

`public.chikado_inquiries`（イベント相談掲示板）

| 列 | 型 | 説明 |
| --- | --- | --- |
| `id` | uuid | 主キー |
| `title` | text | 件名（必須） |
| `desired_period` | text | 希望時期（自由記述・任意） |
| `purpose` | text | 利用内容 |
| `status` | text | `open`（相談中） / `scheduled`（日程確定） / `closed`（見送り） |
| `category` | text | `facility`（施設予約・既定） / `other`（その他の問い合わせ） |
| `source` | text | `staff`（アプリ内から） / `public`（外部向けフォームから） |
| `reservation_id` | uuid | カレンダー化したときの予約 ID |
| `organizer` / `contact_email` / `contact_phone` / `contact` / `staff` / `headcount` / `notes` | — | 予約と同じ項目 |
| `created_at` / `updated_at` | timestamptz | 作成・更新日時 |

## ファイル構成

```
index.html              画面の骨格（ヘッダー・3つのビュー・ダイアログ）
inquiry.html            外部向け 問い合わせフォーム（単独ページ）
css/style.css           デザイン全体（ポスターのトンマナ）
assets/logo.svg         チカ堂ロゴ（縦組み）
assets/favicon.svg      ファビコン
js/config.js            Supabase 接続設定・表示定数
js/api.js               Supabase (PostgREST) の薄いラッパ
js/util.js              日付・時刻ユーティリティ
js/readState.js         既読 / 未読の管理とお知らせの組み立て
js/monthView.js         月別ビュー（1画面1か月・スナップ）
js/threeDayView.js      3日間ビュー（横スクロール＋終日帯）
js/boardView.js         イベント相談掲示板（付箋・外部フォームの共有）
js/publicInquiry.js     外部向け 問い合わせフォームの送信処理
js/app.js               状態管理・フォーム・詳細・お知らせ・イベント配線
```

### ロゴの差し替え

`assets/logo.svg` は公式ロゴの体裁（縦組みの太ゴシック）を再現したものです。
公式のロゴデータ（SVG / PNG）がある場合は、**同名で `assets/logo.svg` を差し替える**だけで
アプリ全体のロゴが入れ替わります（PNG を使う場合は `index.html` の `src` の拡張子も変更してください）。
