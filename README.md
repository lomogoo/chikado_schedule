# チカ堂 SCHEDULE

チカ堂（サンモール一番町・旧金港堂跡地 地下空間）の**施設利用スケジュール管理アプリ**です。

- 📅 **月別ビュー**（縦スクロールで翌月へ）と **3日間ビュー**（横スクロールで他の日へ）
- 🕒 **30分単位**での貸し出し管理（0:00〜24:00）
- 🗓 **複数日にまたがる利用**に対応（期間 × 各日の時間帯）
- 🏷 **仮予約（未確定）** と **本予約（確定）** を区別
- 🔔 予定の追加・更新を**ポップアップで通知**。既読 / 未読は端末ごとに管理
- ⚠️ **実施 1 か月前になった仮予約**を強調表示＋通知
- 📝 利用内容・利用者・**チカ堂担当者**などを記録
- ☁️ データは **Supabase**（PostgREST）で管理
- ⚪️ 白背景のみ（ダークモードなし）／ポスターのトンマナ（墨黒・ピンク・ストーングレー）準拠

ビルド不要の静的サイトです（依存パッケージ 0）。`index.html` を開けばそのまま動きます。

## 画面

| ビュー | 説明 |
| --- | --- |
| 月 | **縦スクロールで翌月・前月がそのまま続けて表示**されます。日付の数字をタップするとその日から 3 日間ビューへ。空白部分をタップで新規予約。 |
| 3日間 | 30 分刻みのタイムグリッド。画面には 3 日ぶんが収まり、**横スクロールで前後の日**を確認できます。空きスロットをタップするとその時間で新規予約フォームが開きます。重なった予約は自動で横に並びます。 |

複数日にまたがる予約は、期間中の各日に同じ時間帯のブロックとして表示され、
`1/4日目` のような通し番号が付きます。

### お知らせ（ポップアップ通知）

ヘッダーのベルに未読件数が出ます。未読があるときは自動でポップアップが開きます。

| 種別 | 条件 |
| --- | --- |
| **新規** | この端末でまだ見ていない予定が追加された |
| **更新** | 前回確認したときから日時・区分・件名が変わった |
| **要確認** | 仮予約のまま実施日が 30 日以内に迫っている |

既読状態はサーバーではなく**この端末の `localStorage`**（予約 ID をキー）に保存されます。
端末ごとに独立して管理されるため、他の人の既読には影響しません。
初回訪問時は既存の予定をすべて既読として扱うため、過去分の通知で埋まることはありません。

「要確認」の予定は、カレンダー上でもピンクの塗り＋`!` マークで強調され、
ヘッダーの「要確認」フィルタで絞り込めます。

### キーボードショートカット

| キー | 動作 |
| --- | --- |
| `←` / `→` | 前 / 次の期間へ |
| `T` | 今日へ |
| `M` | 月別ビュー |
| `D` | 3日間ビュー |
| `N` | お知らせの開閉 |
| `Esc` | ダイアログを閉じる |

## セットアップ

### 1. Supabase 側

セットアップ用の SQL は**リポジトリには含めず、別途共有**しています。
Supabase の **SQL Editor** に貼り付けて実行してください。
このアプリ専用の `public.chikado_reservations` テーブルを新規作成します
（既存の `reservations` テーブルには一切触れません）。

### 2. 接続設定

`js/config.js` に Supabase の URL と publishable key を記載しています。

```js
export const SUPABASE_URL = 'https://tfkzsbwhvhgxbnnfwtou.supabase.co';
export const SUPABASE_KEY = 'sb_publishable_...';
```

publishable key（旧 anon key）は**ブラウザに公開される前提の鍵**なので、リポジトリに含めて問題ありません。
`service_role` キーは絶対にここへ置かないでください。

### 3. ローカルで動かす

ES Modules を使っているため、`file://` ではなく HTTP で開いてください。

```bash
python3 -m http.server 8000
# → http://localhost:8000
```

## データ構造

`public.chikado_reservations`（このアプリ専用。既存の `reservations` とは分離）

| 列 | 型 | 説明 |
| --- | --- | --- |
| `id` | uuid | 主キー |
| `start_date` | date | 利用開始日 |
| `end_date` | date | 利用終了日（単日なら開始日と同じ） |
| `start_time` | time | 開始時刻（30分単位） |
| `end_time` | time | 終了時刻（30分単位・`24:00` まで可） |
| `title` | text | 件名（必須） |
| `purpose` | text | **利用内容**（必須） |
| `status` | text | `tentative`（仮予約） / `confirmed`（本予約） |
| `organizer` | text | 利用者・団体名 |
| `contact` | text | 連絡先 |
| `staff` | text | **チカ堂側の担当者**（任意） |
| `headcount` | integer | 人数 |
| `notes` | text | 備考 |
| `created_at` | timestamptz | 作成日時 |
| `updated_at` | timestamptz | 更新日時（トリガーで自動更新） |

日時を `date` + `time` で保持しているため、タイムゾーン変換による時刻ズレが起きません
（施設予約は常に現地時間＝JST で運用されるため）。

**複数日予約の考え方**：`start_date` 〜 `end_date` の各日を、`start_time` 〜 `end_time` の
時間帯で利用する、というモデルです（例：8/5〜8/8 の毎日 15:00〜22:00）。
日をまたぐ深夜営業は、終了時刻を `24:00` にするか、日ごとに分けて登録してください。

## ファイル構成

```
index.html              画面の骨格（ヘッダー・2つのビュー・ダイアログ）
css/style.css           デザイン全体（ポスターのトンマナ）
assets/logo.svg         チカ堂ロゴ（縦組み）
assets/favicon.svg      ファビコン
js/config.js            Supabase 接続設定・表示定数
js/api.js               Supabase (PostgREST) の薄いラッパ
js/util.js              日付・時刻ユーティリティ
js/readState.js         既読 / 未読の管理とお知らせの組み立て
js/monthView.js         月別ビュー（縦に連なる月ブロック）
js/threeDayView.js      3日間ビュー（横スクロールする日付ストリップ）
js/app.js               状態管理・フォーム・詳細・お知らせ・イベント配線
```

### ロゴの差し替え

`assets/logo.svg` は公式ロゴの体裁（縦組みの太ゴシック）を再現したものです。
公式のロゴデータ（SVG / PNG）がある場合は、**同名で `assets/logo.svg` を差し替える**だけで
アプリ全体のロゴが入れ替わります（PNG を使う場合は `index.html` の `src` の拡張子も変更してください）。
